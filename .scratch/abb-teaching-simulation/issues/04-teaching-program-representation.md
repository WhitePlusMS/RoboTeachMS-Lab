# 04 — 确定教学程序文本与编辑器边界

Type: grilling
Status: resolved
Blocked by: 03
Part of: ../map.md

## Question

首期教学程序由什么数据结构承载，文本编辑、点位记录、解析校验和执行之间如何分工？

需要决定：

- RAPID-like 文本的最小语法和明确不兼容项；
- 指令、点位、工具/工件坐标和数值参数的内部表示；
- 文本是唯一来源，还是文本与结构化指令双向同步；
- 语法错误、参数错误和运动学错误分别在哪里提示；
- 首期是否支持保存、导入、导出，以及使用 localStorage 还是文件下载。

删除测试：去掉编辑器 UI 后，解释执行仍应能接受稳定的结构化程序；去掉解释执行后，文本不能被误报为已经完成仿真。

## Answer

本票决策如下：

- 程序主要载体是 RAPID 文本模块，首期直接编辑代码，不用可视化卡片替代代码。
- RAPID 文本是源头；解析器生成 AST、诊断信息和可执行结构，执行器不直接读取界面组件状态。
- 首期支持明确的 RAPID 子集：模块、过程、注释、数据声明、robtarget/jointtarget 相关数据，以及 MoveJ/MoveL；未支持的语法必须报明确错误。
- 这是纯前端线上应用。程序只存在当前页面内存，不使用 localStorage，不做本地持久化，不提供文件导入导出；刷新页面后程序状态可以丢失。
- 支持从当前机器人姿态示教点位，并把点位写回当前内存中的 RAPID 文本/结构化程序；点位不能只存在独立表格。
- 首期编辑器支持整段运行、当前指令、单步、暂停、停止、复位，并显示程序指针和运动指针。
- GitHub 检索没有找到可直接替换当前项目的完整 ABB RAPID 在线仿真项目。参考项目和使用边界记录在：
  [GitHub 参考项目检索结果](../research/03-github-reference-projects.md)。
- 参考项目只用于语法、真实代码样式、路径案例和 parser/AST/Three.js 组织方式；不直接复制没有明确许可证的代码、RobotStudio 专有资源或其他机器人型号参数。

产品边界再次确认：这是尽可能接近 ABB 的纯前端仿真编程教育平台，不是 ABB 控制器、完整 RAPID 编译器或控制器通信系统。
